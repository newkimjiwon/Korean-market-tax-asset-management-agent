# 근로자 통합 정산

실제 사용자 자료를 저장하지 않는 순수 계산 경로다. 2025·2026년 일반 거주자
근로소득 정산을 지원한다. 연간 규칙의 전체 검증은 끝나지 않았으므로 결과는
`provisional`이며 신고 완료액으로 표시하지 않는다.

처음 준비하는 사용자는 [필요 자료·작성 안내](getting-started.md)를 먼저 확인한다.
보험료와 기납부 세금의 구분, 월별·연간 금액의 구분, 미확인 항목의 처리 방법을 안내한다.

## 실행

```bash
uv sync --extra mcp --extra dev
uv run python -m ktax examples/synthetic_settlement.json --json
uv run python -m ktax.server
uv run pytest
```

예제와 테스트는 실제 사용자와 무관하게 만든 합성 자료다. 실제 사용자 입력은
호스트가 메모리에서 도구에 전달하며 저장소·예제·테스트·문서에 기록하지 않는다.
CLI는 사용자가 제공한 파일을 읽을 뿐 별도 복사나 출력 파일을 생성하지 않는다.
CLI 표준출력에는 계산 결과가 있으므로 호스트의 출력 보관 정책은 별도 적용된다.

## 에이전트 흐름

1. `list_settlement_years`로 지원 연도와 검증 여부를 확인한다.
2. `describe_settlement_fields`로 데이터 종류·질문·원천을 확인한다.
3. `calculate_salary_settlement(data, year)`에 알려진 사실만 전달한다.
4. `next_questions`의 우선 질문(최대 3개)에 필요한 자료를 확보하고 재계산한다.
5. `recommend_salary_actions`로 기존 감면을 유지한 추가 절감액을 계산한다.
6. 여러 변경을 동시에 검토할 때는 `compare_salary_settlements(before, after, year)`를 쓴다.

자료가 여러 출처에서 들어오면 `collect_salary_inputs(records)`를 사용할 수 있다.
각 record는 `year`, `amount_basis`(actual/forecast), `source`, `as_of`, `values`를
갖는다. values는 정산 입력의 부분 객체이며 중첩 객체는 필드별, 배열은 전체 목록
단위로 병합한다. 서로 다른 연도·실적/예상 자료는 병합하지 않는다. 동일 권위
원천이 충돌하면 최신값을 임의 확정하지 않고 `conflict`, `data: null`을 반환한다.
null도 미확인이라는 새 정보로 보존한다. 더 높은 권위의 null은 예전 값을 미확인으로 바꾸고, 같은 권위의 null과 금액은 충돌로 반환한다. 확인한 자료로 충돌을 해결한 후 다시 호출한다. 자료 인증·원본 파싱은 호스트의 역할이다.

## 입력과 상태

- `gross_salary`: 귀속연도 전체 급여·상여, 비과세 포함. `non_taxable_salary`를 한 번 차감한다.
- 연간 예상 입력은 `forecast`, 연간 확정 실적은 `actual`. 올해 누계를 연간 금액으로 자동 환산하지 않는다.
- 누락·null은 미확인, 0·false·빈 목록은 명시적으로 확인한 없음이다.
- 기본공제는 본인을 자동 포함한다. `eligible_dependents`는 자격이 확인된 본인 외 인원이다.
- 보험료는 본인 부담액이다. 회사 부담액을 포함하지 않는다.
- `other_deductions`/`other_credits`는 추가 항목의 자격·개별 한도를 확인한 금액을 받는 확장 경로다.
  자동 계산하는 근로소득공제·본인/부양가족 기본공제·보험료·근로소득세액공제·중소기업 감면·월세·연금계좌를 여기에 중복 입력하면 안 된다.
  카드·주택·의료비 등의 원자료 자동 산출은 이 경로에서 아직 지원하지 않는다.
- `evidence`는 필드 경로·출처·기준일만 기록한다. 이름·회사명·주민번호·주소·계좌번호는 필요 없다.

`invalid_input`은 형식·기간·금액 모순, `indeterminate`는 자료 부족,
`unsupported_scope`는 혼합소득·비거주자·배우자 월세 특례 등 미지원 범위,
`unsupported_year`는 연도 규칙 없음이다. 이 상태에서는 최종 세액을 만들지 않는다.
입력이 충분해도 규칙 검증 미완료 또는 예상 자료이면 `provisional`이다.
`complete`는 연간 규칙 검증 완료 및 실적 입력 조건을 모두 충족해야 한다.

`tax`는 결정세액이고 `settlement`는 기납부액과의 차액이다. 기납부세액이
없으면 세액은 계산할 수 있어도 환급은 `indeterminate`다. `net_due`는
양수면 추가 납부, 음수면 환급이며 소득세·지방소득세 차액도 별도 반환한다.
이미 받은 환급·추징은 기납부 순액에 반영한다.

## 감면·주거 기간

`employment_periods`에 귀속연도 근로기간을 모두 넣는다.
`sme.status`는 `applied`, `eligible_unclaimed`, `not_applicable` 중 하나다.
회사에서 확인한 최초 감면 시작·종료일과 올해 감면 대상 급여를 받는다.
현재 나이·회사명만으로 자격을 판단하지 않으며 이직일로 감면기간을 초기화하지 않는다.
연중 감면 만료 시 급여를 단순 월수 안분하지 않는다. 정확한 대상 급여가 없으면 질문한다.

`rent.status`는 이번 정산에 반영할 `applied` 또는 미신청 `eligible_unclaimed`이다.
계약별 익명 ID로 계약·납부·공적 지원을 연결한다. 지원 대상 월과 수령일을 구분하고
다른 연도의 지원액을 해당 연도 월세에서 빼지 않는다. 지원이 없는 경우도 빈 목록으로
확인해야 한다. 계약별 월세와 지원금은 각각 대상 월별 한 행으로 합산하며 중복 행은 거부한다.

연중 전입·이사·취업은 날짜로 확인한다. 월중 변경은 일할 안분을 추정하지 않고
`eligible_amount`(공제요건 충족 기간 월세, 지원금 차감 전)를 추가 요청한다.
부분기간에 지원금이 있으면 `eligible_support_amount`로 적격 월세에 배분되는 지원액을 확인한다. 지원액 전액을 임의 차감하거나 일할 안분하지 않는다. 적격·비적격 기간의 지원액이 각 기간 월세액을 넘으면 오류로 반환한다.
연도를 넘긴 선납·연체 월세는 귀속 판단을 자동 확정하지 않는다.

## 계산 순서와 비교

총급여 → 근로소득공제 → 기본·연금·보험료·기타 소득공제 → 과세표준 →
산출세액 → 중소기업 감면(대상 급여 비율 및 연간 한도) → 감면에 따라 조정한
근로소득세액공제 → 연금·기타·월세 공제 → 결정세액 → 기납부액 정산.

표준세액공제 경로와 특별소득·세액공제 경로를 각각 계산하여 유리한 경로를
선택한다. 두 경로의 합계는 `alternatives`에서 확인할 수 있다. 각 공제는
`available`(공제 가능액), `used`(실제 사용액), `unused`로 나눈다.

이미 신청한 감면은 신규 신청 추천에서 제외한다. 추가 납입이나 신청 효과가 0이면
그대로 0을 반환하며 자격 미달로 바꾸지 않는다. 추천별 절감액을 합산해서는 안 된다.
통합 비교는 모든 변경을 반영한 최종 세액의 차이만 반환한다.

## 기존 API와의 구분

`Profile`, `estimate_tax`, 기존 카탈로그는 공제총액을 사전에 입력하는 레거시
시뮬레이션이다. 기존 결과의 의미를 바꾸지 않기 위해 자동 근로소득공제를 끼워 넣지
않았다. MCP `estimate_tax_liability`는 핵심 공제·소득 필드 누락 시 계산하지 않고
통합 경로를 안내한다. CLI에서도 핵심 소득·공제 누락 또는 출처 충돌 시 세액·추천 절감액·임계값 숫자를 출력하지 않는다. 입력 방식 혼용·연도 누락·잘못된 JSON은 구조화된 오류로 반환한다.

새 규칙은 `rules/settlement/<year>.json`이며 기존 카탈로그의 연도 규칙과 별개다.
2026년 통합 정산 지원을 기존 ISA·의료비 등 모든 카탈로그의 2026년 검증 완료로
해석하면 안 된다. 각 파일에 검토일·근거·검증 상태·알려진 범위를 기록한다.

## 추가 검토로 수정한 오류

- 비대상 분기라도 사용자가 제공한 값의 형식은 검증한다. 불필요한 질문만 생략한다.
- 세대주에게 다른 세대주의 공제 여부를 요구하지 않고, 세대원에게만 질문한다.
- 비교 결과에 invalid_input/unsupported_year/unsupported_scope를 그대로 보존한다.
- 추정 출처의 값이 있으면 actual로 입력했어도 결과를 complete로 표시하지 않는다.
- 감면 비율에 따른 금액 계산은 정수 나눗셈을 사용하여 순환소수 근사 때문에 1원이 누락되는 오류를 막는다.
